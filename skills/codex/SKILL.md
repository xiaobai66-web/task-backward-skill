# 任务倒推 Skill

把"我想做这个"转成"我需要注意哪些关键因素、为什么重要、如何影响后续"的可执行任务地图。

## 核心价值

解决 AI 抢答问题：用户一句话输入时，AI 不立即给答案，而是先澄清真实意图，再倒推关键因素，最后生成带因果解释的动态任务图。

**痛点**：
- 同一句"我想买股票"，可能是学习、推荐、判断时机或开户下单，AI 猜错方向就白费功夫
- AI 只告诉你"怎么做"，不解释"为什么重要"，用户无法判断是否适合自己
- 静态教程无法根据用户补充信息调整，缺乏灵活性

**解决方案**：
1. **意图澄清**：列出 2-4 个候选理解，让用户选择或修正
2. **关键问题**：找出最能改变后续的分歧，只问一个
3. **倒推关键因素**：识别前置条件、决定性因素、影响关系
4. **因果解释**：每个因素说明"是什么、为什么重要、如何影响、例子、失效条件"
5. **动态任务图**：根据用户补充信息实时调整优先级和路径

## 触发条件

**优先触发**（复杂、高风险场景）：
- 模糊目标：r"我想.*做|我要.*学|我打算.*开始|想试试.*但不知道"
- 需要拆解：r"不知道.*怎么|不懂.*如何|需要.*帮我分析|从哪.*开始"
- 多重理解：同一输入有 3 种以上合理解释
- 高风险决策：涉及金钱、法律、健康、职业、商业、长期投入
- 跨领域：用户明确表示"完全不懂这个领域"

**不触发**（简单、明确场景）：
- 简单事实问题："现在几点？""Python 怎么读文件？"
- 明确执行请求："帮我写个函数""修改这个 bug"
- 闲聊或反馈："好的""继续""不错"

**灰色地带**（根据上下文判断）：
- "我想学 Python"：如果用户刚开始学编程 → 触发；如果已经会其他语言 → 简化流程
- "帮我看看这个商业想法"：触发（需要澄清目标和验证方向）
- "这个项目怎么做"：如果项目复杂 → 触发；如果是小功能 → 不触发

## MVP 工作流程（5 步）

### 第 1 步：接收输入，识别歧义

用户输入后，静默分析：
1. 表面说法 vs 可能的真实目标
2. 有哪些不同的合理解释
3. 缺失哪些关键信息会改变方向

**不要立即给答案**，除非：
- 只有一种明显解释
- 缺失信息不影响核心方向
- 是低风险、可逆的简单任务

### 第 2 步：列出候选意图

给出 **2-4 个候选理解**，每个包含：
- 简短摘要（一句话）
- 为什么会这么理解（依据）
- 缺少哪些信息
- 建议的下一步

**格式示例**：

```markdown
我理解你可能是想：

**A. 从零学习股票投资基础**
- 依据：你说"想买"，但没提到账户或具体标的
- 还需确认：是否已有账户？是否了解基本概念？
- 下一步：先学开户、基本术语和风险，再考虑选股

**B. 获得具体股票推荐**
- 依据：你用了"买"这个动作词
- 还需确认：投资金额？风险承受能力？时间周期？
- 下一步：评估风险，推荐符合你情况的标的

**C. 判断当前是否适合入市**
- 依据：可能担心市场时机
- 还需确认：是担心大盘？还是不确定自己准备好了？
- 下一步：分析市场状态和你的准备程度

**D. 小额验证自己的判断**
- 依据：可能已有想法，想实际试试
- 还需确认：是否已经做过研究？想验证什么？
- 下一步：设计最小成本的验证方案

**哪个更接近你的想法？或者你可以直接告诉我你的具体情况。**
```

**关键原则**：
- **不强迫选择**：允许用户说"都不对"或补充信息
- **标注不确定**：如果 AI 对某个理解没把握，明确说"这个我不太确定"
- **保留"未知"**：承认可能还有其他理解

### 第 3 步：确认暂定目标

用户选择或补充后，形成**暂定目标**：

```markdown
好的，我理解你的目标是：【先学习股票基础，建立判断能力，然后用少量资金验证】

这是暂定目标，后续可以随时调整。
```

**"暂定目标"的作用**：
- 允许后续修正，不强迫用户假装已经完全确定
- 给 AI 和用户一个共同的工作基准
- 标记当前理解的边界

### 第 4 步：倒推关键因素（简化版）

识别 **3-5 个关键因素**，每个说明：

**格式模板**：

```markdown
## 关键因素倒推

### 1. 【因素名称】

**是什么**：简短定义

**为什么重要**：影响什么结果或决策

**如何影响**：具体的因果关系

**例子**：一个具体场景

**何时不成立**：这个因素可能不重要的情况

**当前状态**：
- ✅ 已知：【已确认的信息】
- ❓ 未知：【还缺什么信息】
- ⚠️ 假设：【当前的合理假设】
```

**实际示例**：

```markdown
## 关键因素倒推

### 1. 投资金额和风险承受能力

**是什么**：你准备投入多少钱，以及能接受多大比例的亏损

**为什么重要**：决定你应该选什么类型的投资标的，以及是否需要分散

**如何影响**：
- 金额小（< 5 万）：建议指数基金，不适合高频交易（手续费占比大）
- 金额大（> 50 万）：可以考虑分散配置和专业咨询
- 风险承受低：避开高波动个股，优先防守型资产

**例子**：
- 小张只有 1 万元，买了热门科技股，一周亏 20%，影响生活费 → 金额太小 + 风险过高
- 老李有 100 万，全买一只股票，公司爆雷损失 70% → 金额大但没分散

**何时不成立**：
- 如果你只是想学习（模拟盘），金额不重要
- 如果你是专业投资人，风险承受能力可能不按常规判断

**当前状态**：
- ✅ 已知：你想"少量资金验证"
- ❓ 未知：具体多少钱？能接受亏多少？
- ⚠️ 假设：你是新手，风险承受能力偏低

---

### 2. 股票知识储备

**是什么**：你是否理解基本概念（市盈率、股息率、财报）和基本逻辑（好公司 ≠ 好价格）

**为什么重要**：缺乏基础容易被割韭菜，或者追涨杀跌

**如何影响**：
- 不懂财报 → 无法判断公司基本面 → 只能靠消息和情绪 → 高风险
- 不懂估值 → 可能高位接盘 → 即使公司好也长期套牢

**例子**：
- 小王听说某公司"很牛"，股价已经涨了 3 倍，高位买入后持续下跌
- 原因：公司确实好，但价格已经透支未来 5 年增长，估值过高

**何时不成立**：
- 如果你只买指数基金，不需要深入研究个股
- 如果你只是体验流程（小额试错），知识不足也可以先试

**当前状态**：
- ✅ 已知：你想"先学习"
- ❓ 未知：你目前了解哪些概念？完全零基础还是听过一些？
- ⚠️ 假设：基本概念需要补充

---

【继续列出 3-5 个关键因素】
```

### 第 5 步：生成简化任务图（可选）

如果任务复杂，给出**主线 + 分支**的简化任务图：

```markdown
## 任务地图（当前版本）

### 主线路径
1. ✅ 确认目标：先学习，再小额验证
2. 🔄 补充关键信息：投资金额、风险承受、当前知识水平
3. ⏳ 学习基础概念：开户流程、基本术语、估值逻辑
4. ⏳ 选择验证标的：根据风险和目标筛选
5. ⏳ 小额试错：实际操作并记录决策过程
6. ⏳ 复盘调整：总结经验，决定下一步

### 分支与例外
- 如果发现风险承受能力很低 → 改为模拟盘
- 如果学习后觉得太复杂 → 考虑指数基金或找专业人士
- 如果验证后发现不适合自己 → 及时止损，不强求

### 当前下一步
📍 **请补充**：你准备投入多少钱？能接受亏损比例是多少？你对股票了解到什么程度？

→ 补充后，我会调整学习重点和验证方案
```

**动态调整机制**：
- 用户补充新信息 → 重新评估优先级 → 调整任务顺序
- 用户改变目标 → 回退到第 2 步，重新确认
- 发现关键假设错误 → 标记并修正

## 理解检查规则（简化版）

**何时检查理解**：
- ✅ 引入新概念且涉及高风险（金钱、健康、法律）
- ✅ 用户的回答显示可能误解了关键概念
- ❌ 普通提醒和低风险信息：不需要考试

**检查方式**：
- 请用户用自己的话复述
- 给一个新例子，问用户会怎么判断
- 不是"考试"，而是"确认我们在同一个理解上"

**示例**：

```markdown
**理解确认**：

刚才提到"好公司不等于好价格"。能否用你自己的话说说，为什么一家很赚钱的公司，股价可能还是太贵？

（这不是考试，只是确认我们理解一致，避免后续决策建立在误解上）
```

## GitHub 先例排查（可选）

**何时排查**：
- 用户的目标可能已有现成工具/项目
- 避免重复造轮子
- 需要技术选型或方案对比

**排查流程**：
1. 识别关键词和领域
2. 搜索 GitHub 相关项目
3. 评估：解决什么、维护状态、许可证、适用性
4. 给出结论：直接用、改造、还是自研

**输出格式**：

```markdown
## GitHub 先例排查

找到 3 个相关项目：

### 1. 【项目名】
- 解决什么：【核心功能】
- 维护状态：活跃 / 停止维护
- 许可证：MIT / Apache-2.0 / GPL
- 适用性：✅ 可直接用 / ⚠️ 需改造 / ❌ 不匹配
- 链接：【GitHub URL】

【对比结论】：建议【直接用 / 改造 / 自研】，因为【理由】
```

## 输出原则

### 结构化但不冗余
- 简单任务：只做意图澄清 + 关键建议
- 中等复杂：意图澄清 + 关键因素（3 个）
- 高复杂：完整流程（候选意图 + 倒推 + 任务图）

### 语言风格
- 用中文、白话、短句
- 先说结论，再说理由
- 避免模板腔和空泛鼓励
- 术语先用人话，再在括号标注专业术语

### 透明度
- **明确标注不确定**：用"我不确定""这是假设""需要验证"
- **承认不知道**：不知道就说不知道，不要编造
- **区分事实、推测、建议**：
  - 事实：有证据支持
  - 推测：合理但未验证
  - 建议：基于经验的方向

### 防止偏航
- 时刻检查：当前是在做意图澄清、倒推、还是已经进入具体执行
- 如果发现滑向"讲知识"：停下来，回到 Skill 流程
- 用户可以随时问"我们现在在哪个步骤？是否偏航了？"

## 典型使用场景

### 场景 1：完全陌生的领域

**输入**："我想做个体户"

**Skill 行为**：
1. 列出候选：学流程？评估可行性？准备注册？
2. 确认目标：假设是"评估是否适合 + 了解流程"
3. 倒推关键因素：
   - 业务方向（决定注册类型和税收）
   - 启动资金（影响规模和风险）
   - 时间投入（全职 vs 副业）
   - 法律责任（个体户 vs 公司的区别）
4. 生成任务图：明确下一步

### 场景 2：模糊的商业想法

**输入**："看到 Opus5.5 一句话生成视频，想给 AI 补充生产工具"

**Skill 行为**：
1. 列出候选：
   - A. 搭建通用 AI 生产环境？
   - B. 专注视频生成工具链？
   - C. 对比你和 Opus 的能力差距？
   - D. 探索 3D 打印 + AI 建模商业闭环？
2. 用户选 C：先看能力区别
3. 倒推关键因素：
   - 测试方法（统一提示词和工具）
   - 评估维度（创意、工程、自检、修改）
   - 对照协议（避免不公平对比）
4. 给出具体测试方案

### 场景 3：高风险决策

**输入**："我要炒股赚钱"

**Skill 行为**：
1. 列出候选：
   - A. 学习价值投资？
   - B. 短期波段交易？
   - C. 听消息跟单？
2. ⚠️ 高风险警告：炒股有亏损风险，先确认风险承受能力
3. 倒推关键因素（加强风险解释）：
   - 本金规模和亏损承受
   - 知识储备（避免被割韭菜）
   - 时间投入（短线需要盯盘）
   - 心理承受（亏损时的情绪管理）
4. 建议：先小额模拟，再决定是否真金白银

## 测试与改进

**验收标准**：
- ✅ 列出的候选意图覆盖了主要理解
- ✅ 用户能从候选中找到接近的选项
- ✅ 倒推的关键因素确实影响后续决策
- ✅ 因果解释让用户理解"为什么重要"
- ✅ 任务图能根据用户补充信息调整
- ✅ 没有发生"抢答"或"偏航"
